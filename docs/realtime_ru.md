# Прерывания и потоки

[English version](realtime.md)

## 1. Переносите подготовку данных из ISR в основной цикл

Чтение потока, декодирование кадров и подготовку приращений для интерполяции выполняйте в основном цикле. На каждом событии таймера ISR может переключиться на готовый кадр или забрать из FIFO готовое значение PWM. Разделяйте работу по бюджету в худшем случае. Запишите все данные до обновления индекса, который делает их доступными потребителю.

Доступ к 16- или 32-битному значению может прерваться посередине даже с `volatile`. Снимок 32-битного счётчика, который обновляет ISR, читайте внутри `ATOMIC_BLOCK(ATOMIC_RESTORESTATE)`. Ограничивайте критическую секцию чтением снимка или публикацией и учитывайте время с запрещёнными прерываниями.

## 2. Переносите курсор в младший байт указателя

Выровняйте буфер по границе 256 байт и поместите целиком в одну страницу SRAM. Загрузите старший байт адреса в XH, а курсор используйте напрямую в XL. После `LD ..., X+` XL уже содержит следующий курсор, пока указатель не вышел за страницу. При достижении ёмкости возвращайте курсор к началу. Учтите отступы выравнивания и место под стек, проверьте запись самой большой порции на границе кольца. Сопоставьте выигрыш в ISR с дополнительной памятью на выравнивание.

## 3. Оставляйте арифметические флаги нетронутыми в обычном пути IRQ

Сравнивайте индексы кольца через `CPSE` и выбирайте инструкции пересылки, которые сохраняют арифметические флаги. Ручной ISR может обойтись без сохранения SREG, если ни один путь к RETI не меняет значимые флаги. На устройствах с подходящими GPIOR их можно использовать для временного сохранения состояния, если регистры принадлежат только этому ISR и вложенных прерываний нет. Проверьте пустой FIFO, переход через границу и состояние прерванной программы. Считайте принятие прерывания, переход по вектору и RETI отдельно от ожидания текущей инструкции или разрешения IRQ.

## 4. Ограничивайте самый длинный провал между публикациями

Выбирайте ёмкость FIFO по худшей задержке производителя. Разбиение длинного пополнения на порции может сократить максимальное ожидание новых данных. Запас FIFO измеряйте при полной нагрузке, с включёнными IRQ, разными входными пакетами и реальным темпом SPI и таймера. Учитывайте предзагрузку, старт, сброс и медленные пути, даже если средняя пропускная способность достаточна.

## 5. Исключайте накопление ошибки периода

Если период отсчёта содержит дробную часть такта таймера, накапливайте остаток и корректируйте целый интервал. Например, для периода 12,5 такта можно чередовать 12 и 13. Измеряйте и накопленный дрейф, и джиттер отдельных отсчётов, на который также влияет задержка прерываний. Уточните, когда таймер принимает новое значение сравнения и что происходит при запоздалом обновлении.

```c
struct fractional_period period = {
    .whole_ticks = 12, .remainder = 1, .denominator = 2, .phase = 0
};
uint16_t ticks = period_next_ticks(&period);
```

Сохраняйте состояние `period` между тиками. Пример сравнивает фазу с `denominator - remainder` до прибавления остатка, поэтому он работает и вблизи предела 16-битного счётчика. Функция возвращает интервал в тактах таймера. Переведите его в значение регистра сравнения для выбранного режима. [Реализация](../examples/recipes.h)
