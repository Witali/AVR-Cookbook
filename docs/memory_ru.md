# Память и конфигурация

[English version](memory.md)

## 1. Держите неизменяемые таблицы и строки во Flash

Размещайте неизменяемые таблицы в `PROGMEM` и выбирайте функцию чтения по ширине элемента, например `pgm_read_byte` или `pgm_read_word`. Таблица из 257 16-битных значений содержит 514 байт данных. Через общий интерфейс чтения можно работать с программной памятью и другими носителями. Строки из Flash можно читать по байту и сразу передавать в UART.

```c
#include <avr/pgmspace.h>
#include <stdint.h>

static const uint8_t steps[] PROGMEM = {3, 5, 8, 13};
uint8_t step(uint8_t i) { return pgm_read_byte(&steps[i & 3u]); }
```

На ATmega328P простое снятие `const`/добавление `const` не заменяет выбор адресного пространства: обычное разыменование указателя на `PROGMEM` не выполняет `LPM`. Для классического AVR с данными выше 64 КиБ проверьте адрес в map, используйте дальний доступ с полным байтовым адресом, если он нужен. В ASM адрес таблицы для `LPM` байтовый; адреса переходов и их релокации требуют отдельной проверки. Прогон [Flash против SRAM](../examples/README_ru.md) показывает разницу на связанной сборке.

## 2. Вырежьте неиспользуемые режимы при сборке

Задавайте варианты параметрами сборки, чтобы исключать неиспользуемый код. Например, в mono можно убрать правый микшер, стереоинтерполяцию и запись в неиспользуемый регистр сравнения. Другие параметры могут выбирать реализацию UART, набор команд или поддержку LED. Сравнивайте время и размер на общих функциях и проверяйте каждую конфигурацию. В учебном примере проверьте по дизассемблированию, что mono-сборка не пишет в OCR1AL. [Сравнение сборок](../examples/README_ru.md)

## 3. Экономьте записи EEPROM

Для настроек, которые часто меняются, распределите записи по кольцу слотов EEPROM. `EEPROM.update()` в Arduino AVR программирует байт только при изменении значения. Если запись занимает несколько байтов, предусмотрите восстановление последней целой записи. Проверьте сбой питания после каждой операции, сравнение номеров при переполнении и переход между последним и первым слотом.

## 4. Переиспользуйте память по времени жизни

Переиспользуйте память, когда времена жизни данных не пересекаются. Например, один буфер можно отдать сначала приёмнику, а затем коду подготовки ответа, если прежний потребитель закончил чтение до передачи буфера. Неактивный буфер можно не обнулять, если перед публикацией записываются все байты, доступные потребителю. Проверьте холодный старт со случайным заполнением RAM и регистров, сброс и ранние входящие пакеты. Нулевое начальное состояние симулятора может скрыть ошибки.
