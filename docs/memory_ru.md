# Память и конфигурация

[English version](memory.md)

## 1. Держите неизменяемые таблицы и строки во Flash

В LPC-sound-codec таблица косинуса на 257 знаковых 16-битных элементов хранится в `PROGMEM`, а декодер читает нужные слова через `pgm_read_word`. Сами данные таблицы занимают 514 байт. В MicroMusic один интерфейс чтения скрывает выбор между программной памятью и другими носителями. Строки из Flash тоже можно читать по байту и сразу передавать в UART.

```c
#include <avr/pgmspace.h>
#include <stdint.h>

static const uint8_t steps[] PROGMEM = {3, 5, 8, 13};
uint8_t step(uint8_t i) { return pgm_read_byte(&steps[i & 3u]); }
```

На ATmega328P простое снятие `const`/добавление `const` не заменяет выбор адресного пространства: обычное разыменование указателя на `PROGMEM` не выполняет `LPM`. Для классического AVR с данными выше 64 КиБ проверьте адрес в map, используйте дальний доступ с полным байтовым адресом, если он нужен. В ASM адрес таблицы для `LPM` байтовый; адреса переходов и их релокации требуют отдельной проверки. Прогон [Flash против SRAM](../examples/README_ru.md) показывает разницу на связанной сборке.

## 2. Вырежьте неиспользуемые режимы при сборке

В MicroMusic ATtiny88 профиль mono не включает правый микшер, интерполяцию stereo и запись в OCR1A. У optiboot профиль определяет набор команд и способы UART; в MicroNucleus можно собрать отдельный вариант без LED. Делайте взаимоисключающие профили явными. Отключение канала или команды меняет возможности бинарника; сравнивайте время и размер на общей функциональности, а для каждой конфигурации проверяйте её собственный контракт. Тест mono в MicroMusic отслеживал даже запись в OCR1A того же значения.

## 3. Экономьте записи EEPROM

Для настроек, которые часто меняются, распределите записи по кольцу слотов EEPROM. `EEPROM.update()` в Arduino AVR программирует байт только при изменении значения. Если запись занимает несколько байтов, предусмотрите восстановление последней целой записи. Проверьте сбой питания после каждой операции, сравнение номеров при переполнении и переход между последним и первым слотом.

## 4. Переиспользуйте память по времени жизни

В строгом USB-загрузчике MicroNucleus сборка ответа использует постоянное состояние и счётчики повторно, а Flash-only эксперимент перестаёт очищать неактивные сетевые буферы до момента публикации. Такой приём экономит код или SRAM, если чтение возможно только после полной записи. Инициализируйте всё, что уже доступно потребителю. Прогоняйте холодный старт со случайным заполнением RAM и регистров, а также reset и ранние входящие пакеты; нулевое начальное состояние симулятора маскирует ошибки.
