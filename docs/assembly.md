# AVR-ассемблер

Эти приёмы полезны после просмотра связанного кода. Если AVR-GCC уже выдаёт ту же последовательность, предпочтите исходник на C. Проверьте набор инструкций и время исполнения именно для своего ядра.

## 1. Используйте результат инструкции и её флаги

В историческом optiboot ATmega328P `LSR` переводит байты в слова, одновременно выставляя C для нечётного исходного числа и Z для нулевого результата. Это сэкономило 2 Б у проверки чётности и диапазона. В MicroNucleus конечное значение счётчика после `SBIW` уже равно нулю: пригодно для обнуления пары регистров через `MOVW`, если счётчик точно исчерпан на всех входах. Между установкой и чтением флага не должно быть инструкции или вызова, меняющего его.

## 2. Сцепляйте сравнения через CPC

Для беззнакового 16-битного сравнения сравните младший байт первым. `CPC` использует перенос от `CP` и сохраняет Z установленным лишь при равенстве уже сравненных частей и текущего байта.

```asm
; a = r25:r24, b = r23:r22
cp   r24, r22
cpc  r25, r23
breq equal
; здесь BRLO может проверить a < b, пока C не испорчен
```

В Flash-only MicroNucleus цепочка проверки длины, адреса и CRC токена сэкономила 4 Б и два такта на валидном токене. Изменение вынудило заново подобрать задержку приёма; проверки границ SOP дали свидетельство только для соответствующего пути. Две версии проверки равенства есть в [примерах](../examples/README.md).

## 3. Переиспользуйте указатель и держите состояние в регистрах

MicroMusic читает последовательные данные через `LD Rd, X+` или `LPM Rd, Z+` на подходящих ядрах, держит аккумулятор MAC в регистрах и использует `MOVW` вместо двух переносов между парами с чётными номерами. В MicroNucleus замена `STS` на `STD Z+20` сэкономила 2 Б при тех же двух тактах: на всех путях до записи Z уже указывал на базу контекста. Это доказательство о времени жизни указателя; если придётся загружать базу специально, пересчитайте размер и задержку. `STD` с положительным смещением работает с Y/Z и ограниченным диапазоном смещения.

## 4. Сокращайте ветвления, учитывая все пути

Поставьте тело простого случая рядом с условием и поменяйте направление ветки, чтобы убрать лишний переход. В MicroNucleus так перестроили обработку GET_CONFIGURATION. В счётных циклах MicroMusic использует обратный отсчёт с `DEC/BRNE`: для диапазона 0…255 отдельно обработайте ноль, иначе короткий цикл выполнит 256 итераций. Дальний адрес ветки, изменение взятого пути или размера пропускаемой инструкции может изменить выигрыш.

## 5. Обращайтесь к битам прямо лишь при подходящем регистре

На классических AVR `SBI/CBI/SBIC/SBIS` адресуют нижние 32 адреса **пространства I/O**, а не 32 произвольных адреса SRAM. MicroNucleus использовал `SBI` для PCIF2 в PCIFR на ATtiny88: три замены дали −6 Б при сохранении двух тактов на операцию. Нельзя автоматически заменять запись маски в другой регистр с семантикой write-one-to-clear обычным read-modify-write. Сверьте поведение выбранной инструкции и регистра по даташиту, включая соседние флаги.

## 6. Сохраняйте контракт ABI и прерываний

На классическом ABI AVR-GCC `MUL` пишет в `r1:r0`; перед возвратом или вызовом C восстановите ноль в r1. Прерывание может прийти в середине частного ASM, когда r1 ненулевой. Обычный ISR компилятора при использовании нулевого регистра сохраняет, обнуляет и восстанавливает его; ручной ISR должен сохранять прерванное состояние. При вызове из C также сохраняйте изменённые callee-saved регистры. Для inline ASM опишите раннюю перезапись выходов и эффекты на память в ограничениях и clobber-списке. У AVR Reduced Core другой ABI.

В Speex из MicroMusic убрали только избыточные очистки r1 внутри частной цепочки умножений, сохранив очистку перед потребителем нуля. На ATmega328P это дало −12 Б Flash; в трёх путях ядра 240/330/420 → 238/327/416 тактов с RET и без CALL. В модели прерывание вводили и при ненулевом r1. Убирать очистку на границе с C из этого результата нельзя.
