# Integer arithmetic

[Русская версия](arithmetic_ru.md)

## 1. Choose integer widths from proven bounds

If a signed waveform code ranges from −8 to 7 and its level from 0 to 15, the product ranges from −120 to 105 and fits in a signed byte. Multiplying the sum of eight such codes by the same level requires a wider type. On a target without `MUL`, compare a lookup table with a bounded sequence of additions. Count table alignment and worst-case cycles, including the effect on FIFO headroom with interrupts enabled.

Widen operands **before** the operation. On AVR, when multiplying two `int16_t` values, cast at least one operand to `int32_t` if you need the full result. Preserve how the algorithm rounds negative values. C division truncates toward zero, while the arithmetic right shift generated by GNU AVR rounds down. Check the input range and rounding behavior before replacing a division with a shift.

## 2. Select implementations based on the MCU's capabilities

Keep a C reference and select specialized kernels according to device capabilities. For example, ATmega328P supports `MUL` and ATtiny88 does not. Keep implementation flags separate from the compiler's device macros. Set the exact `-mmcu`, check `__AVR_HAVE_MUL__` when hardware multiplication is required, and include the device header. Inspect the linked listing to see what a multiplication helper does. Measure the full firmware separately from an arithmetic probe.

## 3. Start a MAC accumulator with the first product

If the accumulator starts at zero and the input always contains at least one element, initialize it with the first product. This can eliminate the explicit zeroing and first addition. Inspect the linked instructions to see whether the compiler already took this approach. Preserve the original rounding and overflow behavior and handle empty input explicitly where it is allowed.

## 4. Reuse products for related coefficients

To obtain results for coefficients 7 and −14, double and negate the first product if the intermediates fit and the accumulators retain their original precision. For paired filters, compare both outputs and accumulator states. Preserve the order of sign changes, saturation, and rounding. Measure whether the extra arithmetic and live registers cost less than the second multiply.

## 5. Use a divider sized to the proven range

When the numerator has a known upper bound, a bit-at-a-time divider can skip the leading bits that are always zero. Establish bounds for the numerator, divisor, and remainder. Check division by zero and overflow at each step. Compare quotients and remainders with an independent reference, then measure code size and worst-case cycles.

## 6. Measure size and speed separately

A shared routine can save Flash at several call sites, while inlining a single call can eliminate call and return overhead. Remove forced `always_inline` when it prevents sharing and compare the linked images. Check latency and stack usage as well as Flash size before choosing a variant.

## 7. Move search and precomputation to the host

If a stream already has fields for gain or filter parameters, have an offline encoder choose those values. The AVR can use the existing per-sample path. Compare stream size, output quality from the **actual fixed-point decoder**, and FIFO headroom.
