# Integer arithmetic

[Русская версия](arithmetic_ru.md)

## 1. Choose integer widths from proven bounds

In UM88, the signed waveform code ranges from −8 to 7 and its level ranges from 0 to 15, so the product ranges from −120 to 105. Multiplying the sum of eight voices requires a wider type. On ATtiny88, which lacks `MUL`, a bounded number of additions replaced a 256-byte table. The final profile was tested with interrupts enabled. Other variants exceeded the FIFO budget. Check the code size, alignment, and worst-case cycles of each branch to measure the net gain.

Widen operands **before** the operation. On AVR, when multiplying two `int16_t` values, cast at least one operand to `int32_t` if you need the full result. Preserve how the algorithm rounds negative values. C division truncates toward zero, while the arithmetic right shift generated by GNU AVR rounds down. Check the input range and rounding behavior before replacing a division with a shift.

## 2. Select implementations based on the MCU's capabilities

LPX keeps a C reference and separate assembly implementations for AVR5 with `MUL` and AVR25 without it. Keep implementation flags separate from the compiler's device macros. Set the exact `-mmcu`, check `__AVR_HAVE_MUL__` when hardware multiplication is required, and include the device header. Inspect the linked listing to see what a multiplication helper actually does. MicroMusic's test built the arithmetic probe for ATmega328P, ATtiny88, and ATtiny13A. Fitting the entire decoder on ATtiny13A would require measuring the full image.

## 3. Start a MAC accumulator with the first product

If the accumulator starts at zero and the input always contains at least one element, initialize it with the first product. In MicroMusic's Speex code, this change, `MOVW`, and a shorter signed negation together saved 360 cycles per block of 40 samples. In the full ATmega328P decoder, NB8 used 1.45% less time on average and 36 fewer bytes of Flash. WB12.8 used 1.17% less time on average and 72 fewer bytes of Flash. Preserve the original rounding and overflow behavior and handle empty input explicitly where it is allowed.

## 4. Reuse products for related coefficients

To obtain results for coefficients 7 and −14, double and negate the first product if the intermediates fit and the accumulators retain their original precision. In MicroMusic's paired QMF, sharing the 7/−14 product eliminated 80 executions of `MUL` per kernel call. The isolated measurement showed a reduction of 160 cycles and 8 bytes of Flash. Compare the full outputs and both accumulator states. Preserve the order of sign changes, saturation, and rounding.

## 5. Use a divider sized to the proven range

When a numerator has fewer significant bits, the divider can skip its leading zeros. The specialized divider in MicroMusic's Speex WB3.95 took 194–322 cycles including RET. A screening run over 384 frames measured a 0.677% average reduction in time and an 8-byte increase in decoder size. Before applying the technique, establish bounds for the numerator, divisor, and remainder. Check zero handling and overflow at each step. An independent implementation can serve as a reference.

## 6. Measure size and speed separately

Removing `always_inline` in LPX allowed AVR-GCC to share one Q14 function between two call sites. Across ten full ATmega328P images, the change saved 38 bytes of Flash and kept SRAM usage the same. The paired tests measured a 1.63–4.01% increase in decode time. MicroNucleus inlined its sole call to the CRC routine and saved 4 bytes by eliminating the `RCALL/RET` pair. Base the decision on the linked image and the available time margin.

## 7. Move search and precomputation to the host

LPX can prepare gain scaling in the offline encoder using fields already present in the stream. The AVR runs the same operations per sample. This can improve quality at the same bitrate limit. Compare stream size, output quality from the **actual fixed-point decoder**, and FIFO headroom. Use this approach when the data can be prepared ahead of time.
